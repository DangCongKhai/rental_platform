# Security requirements

Use architecture security design and FR05/43/74/86/88. Demonstrate private resource isolation, server validation, negative/admin authorization, exact-contract/hash decisions and transport-appropriate CSRF evidence. Prevent XSS/injection, forged actors, public private-contract buckets and shared-cache favourite leakage. Rate-limit report/auth-sensitive actions. Teacher Sanctum substitution is a tracked decision, not silently waived.

Validation is part of feature/engineering issues and PR evidence. Tool versions/configuration must match the local installed framework; no invented pass result.
