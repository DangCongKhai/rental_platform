# Five-sprint reference plan
This is the teacher's5week template, not five guaranteed remaining weeks. Local AI first records completed work and real deadline/capacity, then adjusts. Never reset existing TODO/issues or create duplicate setup/design tasks.

| Sprint | Primary integrated outcome | Parallel bounded work | Evidence |
|---|---|---|---|
| 1 | Repo audit, contracts, auth/profile, migrations/seeds and first owner property/unit slice | D admin shell+fixtures; C public card/heart component; B upload shape | Issue/branch/PR workflow, source decisions and initial tests |
| 2 | Owner inventory/media/policies/amenities plus draft→first review→publish | C search/detail/favourites; D review queue/reason forms | Resource CRUD, actual external storage API, responsive states |
| 3 | Pending requests→proposal→exact-version mutual confirmation | C private dashboards/forms; D report screens; B report actions | Real PostgreSQL overlap and negative authorization tests |
| 4 | Corrections/renewals/expiry/15day jobs and durable delivery | Cache/resource optimization and remaining admin integration | Retry/concurrency coverage, Scramble, slow query/critical/server alerts |
| 5 | Cross-module regression, operational rehearsal and submission | Root README/screenshots, accessible demo script, individual reports | >70% UI/business and API coverage, <=10min720p demo and final evidence matrix |

Run basic CI/tests and collect evidence every sprint, not only Sprint5. Course monitoring is required; schedule it before final week. Deferred maps/reviews/Google OAuth are not added to fill idle time until core and grading work is stable.
